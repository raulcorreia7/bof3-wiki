This site covers file formats, memory layouts, record tables, text encoding and the code that reads
them. It is written for modders and fans who know some PlayStation basics but not this game. Every
page states layouts, offsets, values and limits, and marks what is unknown.

## What the game is made of

1. **One resident program.** `SLUS_004.22` loads at boot and stays in RAM until power-off. It holds
   the main loop, the loader, the graphics and sound drivers and the shared helpers
   ([programs](./data/programs/)).
2. **Overlays.** All other code streams from `.EMI` archives on the disc into fixed RAM windows. A
   window holds one overlay at a time: the battle program, a scenario controller or the program of
   one map ([loading](./concepts/loading/), [memory map](./concepts/memory/)).
3. **Data tables.** Items, abilities, enemies, text, maps and sound are payloads inside the archives.
   The game reads them through fixed tables and offsets ([game records](./data/records/),
   [game text](./data/text/)).

An EMI archive is a sector-aligned list of typed entries ([EMI container](./formats/emi/)). Each
entry names the RAM address it loads at, so one archive can carry code, data, textures and audio.

## About this site

The pages describe one release, the US disc `SLUS-00422`. [Game version](./appendix/version/) lists its Redump checksums.

The site holds no game data and no game assets. _Breath of Fire_ and the game belong to Capcom, and
the PlayStation belongs to Sony; they keep their rights. This site is independent and is not
affiliated with or endorsed by either company.
